# Complexity Trajectory

When `/complexity` is invoked, preserve all trailing text as task input;
otherwise use the active algorithm or selected code.

1. Read `../skills/complexity-coach/SKILL.md`.
2. Inspect input constraints, loops, recursion, structures, allocations,
   amortization, and hidden library work.
3. Derive bounds step by step and compare meaningful alternatives.
4. Keep analysis read-only unless optimization is explicitly requested.
5. Return assumptions, dominant terms, tightest bounds, and evidence concisely;
   label expected, amortized, and measured claims.
